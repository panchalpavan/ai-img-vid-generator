# Gotchas & Sharp Edges

## Next.js 16 — read the docs, don't assume

This version has breaking changes from what most training data knows. **Before writing any Next.js code**, read the relevant guide in:

```text
node_modules/next/dist/docs/
```

Heed deprecation notices — APIs you know may have changed signatures or been removed.

## Tailwind CSS 4 — no config file

Tailwind 4 uses a CSS-native configuration model. There is **no `tailwind.config.js`**. All theme customization happens in `apps/web/app/globals.css` using `@theme {}` blocks and CSS custom properties.

## Tailwind 4 strips `cursor: pointer` from buttons

Native browser default is no cursor change on `<button>`. Tailwind 4 matches that. We added `cursor-pointer` to the Shadcn `Button` base class and to `DropdownMenuItem` in `apps/web/components/ui/`.

## React 19 — new APIs

React 19 ships `use()`, `useActionState`, `useFormStatus`, `useOptimistic`, and changes to `ref` handling (no more `forwardRef` needed). These are available and preferred over older patterns.

**Next.js 16 ESLint flags `useEffect(() => setState(...))`** as "cascading renders." Derive values from existing state instead (Sprint 2 pattern in `generation-view.tsx`).

## Server vs Client Components — the boundary

Passing a non-serializable value (function, class instance, Date) from a Server Component to a Client Component will throw at runtime. Keep the boundary clean: only pass plain objects, strings, numbers, and arrays across it. Use Server Actions for callbacks.

## Auth.js v5 — JWE by default; we force JWS

The default Auth.js session token is a **JWE** (encrypted), which PyJWT on the backend cannot decode. We override `jwt.encode`/`jwt.decode` in `apps/web/auth.ts` to produce **HS256 JWS** so FastAPI can verify with the same shared secret (`AUTH_SECRET` ↔ `JWT_SECRET`). See ADR-0009.

## Auth.js JWT cookie is HttpOnly

JavaScript can't read the JWT cookie directly. `apps/web/app/api/auth/token/route.ts` is a server-side relay that reads the cookie and hands the JWT to authenticated client-side fetches. Required for any `Authorization: Bearer` call to FastAPI from the browser.

## Shadcn 4.x switched from Radix UI to Base UI

Shadcn's menu components now wrap **`@base-ui/react`**, not Radix. Two real gotchas:

1. **`MenuItem` uses `onClick`, not Radix's `onSelect`.** Your handler will silently no-op if you use `onSelect`.
2. **`MenuLabel` must live inside a `MenuGroup`.** Throws `MenuGroupRootContext is missing` if you forget.

## Supabase moved everyone to the connection pooler

Direct DB connections (`db.PROJECT.supabase.co`) are IPv6-only on new projects and unreachable from most networks. Use the **pooler** URL: `aws-X-REGION.pooler.supabase.com:5432`. Username is `postgres.PROJECT_REF`, not just `postgres`. Documented in `apps/api/.env.example`.

## Alembic + SQLModel — `import sqlmodel` needed in every migration

SQLModel uses `sqlmodel.sql.sqltypes.AutoString`, which Alembic's default `script.py.mako` template doesn't import. We've patched our template (`apps/api/alembic/script.py.mako`) to always include `import sqlmodel`. New autogenerated migrations work out of the box.

## Python `Enum` → SQLAlchemy → Postgres ENUM by default

When you annotate a field as `type: SomeStrEnum`, SQLAlchemy auto-creates a Postgres ENUM type. **Altering Postgres ENUMs via Alembic is painful.** Force VARCHAR explicitly:

```python
type: SomeEnum = Field(sa_column=Column(String(32), nullable=False, index=True))
```

Used by `TransactionType` and `GenerationStatus`.

## `datetime.utcnow()` is deprecated (Python 3.12+)

Use `datetime.now(UTC)` instead. Returns timezone-aware datetimes that don't bite you on comparisons or serialization.

## Celery worker doesn't auto-reload

uvicorn's `--reload` watches API code; the Celery worker started by `npm run dev:worker` does NOT. After any change to `apps/api/app/tasks/*.py` (or anything imported by a task — adapters, models, etc.) **restart `npm run dev`** to pick it up. uvicorn alone won't catch it.

## `.env` changes also need a process restart

Pydantic Settings reads `.env` once at process construction (via `@lru_cache`). New env vars added to `.env` won't take effect on the running process. **Restart `npm run dev`** after editing `.env`.

## Gemini free tier may have `limit: 0` for specific models

Some accounts see `Quota exceeded ... limit: 0, model: gemini-2.0-flash` (or `gemini-2.5-flash-image`) — meaning the free tier doesn't include that model on that account. We work around this by registering multiple providers in a cascade (Pollinations FLUX is currently the working free image provider).

## Pollinations.ai needs proper headers or returns 403

Pollinations sits behind Cloudflare, which 403s requests with the default `Python-urllib/3.12` User-Agent (bot detection). The `PollinationsAdapter` sets a real-looking UA + `Referer` header + `referrer` query param. Don't strip these.

## `google.generativeai` SDK is deprecated

We're on the deprecated `google.generativeai`. The new SDK is `google.genai` (note: no "generative" in the package name). Current code still works; migration is parked.

## Image data URIs need a wide `result_url` column

Sprint 3.5 stores base64-encoded image data in `generations.result_url`. The column is VARCHAR(10MB) to fit images up to ~7MB raw. When R2 lands in Sprint 4, this becomes a short URL and we can shrink the column.

## `npm run lint` — no `--max-warnings`

The current `eslint` script in `apps/web/package.json` is bare. Any ESLint warnings pass silently. When tightening, add `--max-warnings=0`.

## No frontend test runner configured

`apps/web` has zero tests. Before writing the first frontend test, install vitest:

```bash
npm install -D vitest @vitejs/plugin-react @testing-library/react @testing-library/user-event jsdom --workspace apps/web
```

Then add a `vitest.config.ts` and a `"test"` script. Backend has pytest already wired in `apps/api`.

## `npm run build` as the final gate

`next build` runs ESLint + TypeScript checking + the actual build. Always run `npm run build:web` and `npm run lint:api && npm run typecheck:api && npm run test:api` before declaring frontend or backend work done.

## Orphan processes on dev ports

If `npm run dev` shuts down with "Address already in use," a previous Node or uvicorn process is holding the port. Cleanup recipe:

```bash
lsof -ti :3000,:8000 -sTCP:LISTEN | xargs -r kill -9
pkill -9 -f "next dev"
pkill -9 -f "uvicorn app.main"
pkill -9 -f "celery -A app.tasks worker"
```

Use after any session where you killed an `npm run dev` ungracefully (Ctrl+C twice, terminal close, etc.).
